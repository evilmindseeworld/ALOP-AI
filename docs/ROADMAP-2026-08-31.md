## P0 — before anything else (days 1–4)

### 1. Turn `COUNCIL_TOOLS` on, and watch it

The loop is built, tested and deployed **dark**. It has never run against a
real gateway. Everything below assumes it works; nothing has shown that it does.

- Set `COUNCIL_TOOLS=1`. Watch `[TOOLS]` lines: rounds, unique calls, answers.
- The number to watch is **unique calls vs members**. If seven members produce
  seven unique calls every round, the dedupe is not earning its place and the
  prompt needs to push harder toward shared phrasing.
- Failure mode to expect first: models emitting prose *and* a fenced block, or
  a block that never closes. Both are handled — confirm they are actually
  happening rather than trusting the tests.
- Revert is one env var, no deploy.

**Done when:** a real turn shows ≥2 rounds with a dedupe hit, and the answer
cites a URL the router would not have found.

### 2. CI

`.github/` still has no workflows. 393 + 168 tests and a clean build run only
when someone remembers, and this repo now has a cascade baseline that is
regenerated by hand — exactly the thing that rots silently.

One workflow: `npm test` both sides, `npm run build`, on push and PR.

**Done when:** a deliberately broken commit on a branch goes red.

### 3. Rate limiting is per-instance

`express-rate-limit` uses an in-memory store. Every limit multiplies by the
instance count. One instance today, so the limits hold — verified above — but
this is a ceiling on the fix that shipped, and scaling Render is a one-click
action that would silently undo it.

Fix: a shared store. Until then, **do not scale the Render service** without
doing this first.

## P1 — the product (days 5–16)

### 4. SSE activity trail — design step 8

The loop runs before the stream opens, so tool progress is invisible: the user
waits up to 25 s at a spinner. The design already specifies the events
(`tool_start`, `tool_result`) and the frontend shape (a collapsible trail above
the answer). This is the single biggest perceived-quality win left, and it is
the thing that makes the council *look* like it is working rather than hanging.

Needs: open SSE before the loop, emit events, render the trail, and handle the
error path — once headers are sent, a failure can no longer be a 500 JSON.

### 5. `read_file` — design step 6

Blocked on an upload path for non-images (PDF, txt, md, csv) plus text
extraction. The tool takes an **opaque id, never a path**, resolved against a
store scoped to `(user, chat)`. The repo is public and the process holds live
Stripe and Supabase credentials, so there is no allowlist of directories that
makes `read_file("../../.env")` safe to attempt.

### 6. Exercise dictation and regenerate in a browser

Both were fixed in `1ec77a0` and are covered by tests. **Neither has ever been
used in the real app.** Voice input has never worked in this app's history, so
nobody has seen it succeed. Tests do not know that.

### 7. Overlay assistant has no tests

144 lines over `getDisplayMedia`, `SpeechRecognition` and `speechSynthesis`,
none of which exist in jsdom. It is also the only screen-capture surface in the
app, so it is the piece most worth not shipping blind.

## P2 — hardening and debt (days 17–24)

### 8. Admin terminal — allowlisted, read-only

Decided shape: a fixed set of diagnostics (git log, disk, health, migration
status), `is_admin` gated, audit-logged. **No arbitrary strings, no shell
interpolation, no user-supplied arguments concatenated into a command.** It
cannot become RCE by construction, which is the only version worth putting on a
box that holds the service-role key.

### 9. Four unmounted motion primitives

`AnimatedTabs`, `BorderTrail`, `Spotlight`, `TextShimmer` have no importer.
Delete them or use them. They are currently counted as a component layer in
anyone's mental model of the app.

### 10. `frontend/src/.env` is dead config

Wrong directory (Vite reads the project root) and wrong variable name
(`VITE_API_URL` vs the code's `VITE_API_BASE`). Production is unaffected. The
cost is that it looks like the place to point the frontend at another backend
and editing it does nothing.

### 11. `run_code` — design step 7

Ephemeral microVM, no network, no environment, hard timeout. Needs a vendor key
that does not exist. `node:worker_threads` was considered and rejected: it
shares the process, so the isolation boundary is V8's, and on the other side of
it is a live Stripe secret key.

## The two ways this slips

**Enabling `COUNCIL_TOOLS` late.** It is the largest untested surface in the
codebase and the only one whose failure mode is "the answer is quietly worse".
Every day it stays dark is a day of not knowing. It is P0.1 for that reason and
not because it is the most finished.

**Treating the cascade baseline as a formality.** It caught a real regression
this week — a stagger that silently deleted the app's only shimmer, and which
rendered identically at rest. Regenerating it to make a test pass, rather than
reading the index-stripped diff, throws away the one guard that sees changes
review does not. A raw diff that does not shrink when indices are stripped
means something structural moved; read it before regenerating.
